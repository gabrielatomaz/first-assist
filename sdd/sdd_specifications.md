# FIRST Assist - SDD Specifications

This document expands the FIRST Assist user stories into detailed specifications for a Spec-Driven Development (SDD) process.

## Technology Stack
* **Backend:** Node.js (e.g., with Express.js)
* **Database:** MongoDB (using Mongoose as ODM)
* **Frontend:** Vue.js (with Vue Router for navigation and Pinia for state management)

---

## 1. Data Models (MongoDB)

These are the primary Mongoose schemas required for the application.

### `User` Collection
Represents the volunteers and administrators using the app.
* `_id`: ObjectId
* `name`: String
* `role`: String (Enum: `['ADMIN', 'FTA', 'CSA']`)
* `email`: String (Unique, Indexed)
* `passwordHash`: String
* `createdAt`: Date

### `Incident` Collection
Represents a technical problem reported during the event.
* `_id`: ObjectId
* `teamNumber`: Number
* `matchNumber`: String (Optional)
* `description`: String
* `audioUrl`: String (Optional, URL to blob storage for voice reports)
* `status`: String (Enum: `['OPEN', 'INVESTIGATING', 'RESOLVED']`, Default: `'OPEN'`)
* `reportedBy`: ObjectId (Ref: `User`)
* `assignedTo`: ObjectId (Ref: `User`, Optional)
* `createdAt`: Date
* `resolvedAt`: Date (Optional)
* `rootCause`: String (Optional, filled on resolution)
* `appliedSolution`: String (Optional, filled on resolution)

### `Comment` Collection
Represents updates or communication regarding a specific incident.
* `_id`: ObjectId
* `incidentId`: ObjectId (Ref: `Incident`, Indexed)
* `authorId`: ObjectId (Ref: `User`)
* `text`: String
* `createdAt`: Date

### `AISuggestion` Collection
Represents the diagnostic suggestions generated by the AI for an incident.
* `_id`: ObjectId
* `incidentId`: ObjectId (Ref: `Incident`, Indexed)
* `suggestedCause`: String
* `suggestedSolution`: String
* `rating`: String (Enum: `['HELPFUL', 'NOT_HELPFUL', 'UNRATED']`, Default: `'UNRATED'`)
* `createdAt`: Date

## 2. Frontend Specifications (Vue.js)

### 2.1 Views / Pages
* **`LoginView.vue`:** Authentication page. Dispatches login action to Pinia store.
* **`DashboardView.vue`:** Displays a real-time list or grid of open/investigating incidents. Uses WebSockets or polling to update.
* **`IncidentCreateView.vue`:** Contains the form to report a new incident, including the voice recording interface.
* **`IncidentDetailView.vue`:** Shows the full details of a single incident. Includes the `CommentSection` and `AISuggestionPanel` components.
* **`KnowledgeBaseView.vue`:** A search page for querying resolved incidents.

### 2.2 Core Components
* **`IncidentCard.vue`:** Reusable component displaying high-level details of an incident (Status, Team #, brief description). Used in the Dashboard.
* **`VoiceRecorder.vue`:** A UI component that hooks into the browser's MediaRecorder API to capture audio, display a recording timer/waveform, and emit the audio Blob to the parent view.
* **`AISuggestionPanel.vue`:** Displays the AI-generated cause and solution, and includes thumbs-up/thumbs-down buttons to trigger the rating API.
* **`CommentSection.vue`:** Renders a list of comments and provides an input field to add new ones.

## 3. Detailed Specifications by Epic

### Epic 1: User Authentication & Role Management
* **Backend Endpoint:** `POST /api/auth/login`
  * **Payload:** `{ "email": "...", "password": "..." }`
  * **Response:** `{ "token": "...", "user": { "_id", "name", "role" } }`
* **Frontend Flow:** `LoginView.vue` captures credentials -> Node.js validates and returns JWT -> Vue stores JWT in `localStorage`/Pinia -> User is pushed to `DashboardView.vue`.
* **Acceptance Criteria:** Vue Router must use route guards to prevent unauthenticated access to the Dashboard.

### Epic 2: Incident Reporting & Creation
* **Backend Endpoint (Text):** `POST /api/incidents`
* **Backend Endpoint (Voice):** `POST /api/incidents/voice` (Handles `multipart/form-data`)
* **Frontend Flow:** `IncidentCreateView.vue` allows FTA to fill a form OR use `VoiceRecorder.vue`. Upon submission, a request is made to Node.js which saves the document in MongoDB.
* **Acceptance Criteria:** The UI must display a loading state while the voice transcription is processing on the backend.

### Epic 3: Real-Time Tracking & Communication
* **Backend Endpoints:**
  * `GET /api/incidents` (Dashboard list)
  * `PATCH /api/incidents/:id/status` (Update status)
  * `POST /api/incidents/:id/comments` (Add comment)
* **Frontend Flow:** `DashboardView.vue` fetches all incidents on mount. `IncidentDetailView.vue` allows a CSA to change the status via a dropdown, sending the PATCH request.
* **Acceptance Criteria:** Changing a status immediately reflects on the local Vue state and triggers a notification for other connected users (if websockets are implemented).

### Epic 4: AI-Powered Troubleshooting
* **Backend Endpoints:**
  * `GET /api/incidents/:id/ai-suggestions`
  * `PATCH /api/ai-suggestions/:id/rating`
* **Frontend Flow:** When opening `IncidentDetailView.vue`, the `AISuggestionPanel.vue` automatically requests suggestions if none exist.
* **Acceptance Criteria:** The backend Node.js server securely communicates with the AI service (e.g., Gemini API) to generate suggestions based on the incident's `description`.

### Epic 5: Knowledge Base & History
* **Backend Endpoint:** `GET /api/incidents/search?query=...`
* **Frontend Flow:** `KnowledgeBaseView.vue` contains a search bar. Debounced inputs trigger the search endpoint.
* **Acceptance Criteria:** The Node.js API uses MongoDB's `$text` or regex search capabilities to find matching `RESOLVED` incidents based on `rootCause` and `appliedSolution`.
